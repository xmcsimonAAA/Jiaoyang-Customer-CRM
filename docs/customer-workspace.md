# 客户中心与两个产品业务

2026-09-16：侧边栏按日常工作、客户中心、产品业务、系统管理组织。

- 日常工作：工作台、我的跟进。
- 客户中心：全部客户，按已确认 TW 汇总；没有 TW 的旧客户按内部 ID，港安待匹配记录按批次与稳定记录键保留，绝不按同名自动合并。
- 定增：批次管理、业务客户、资料录入、导入复核、负责人分配、经纪人绑定、业务表头、业务跟进。原路由兼容。
- 优先劣后：批次记录、客户综合查询、资料导入、上传历史、负责人分配、业务跟进。
- 系统管理：人员与权限、操作日志。

## 客户卡片和权限

卡片汇集当前账号有权查看的定增资料、优先劣后资料、共用资产与持仓、跟进时间线。已关联 TW 的两个产品统一依据客户主档归属、团队与协同关系控制访问；尚未关联 TW 的活动暂按活动指派控制访问。未参与产品与无可见产品资料不混作同一概念。

2026-09-17 起，权威总名单按 TW 补入现有客户主表，定增和优先劣后共用身份。已有姓名、负责人、定增状态和金额保持原值；新 TW 创建待分配客户，不生成产品参与记录。联系方式仍从有权查看的旧客户记录读取，优先劣后批次保留自己的经纪人、协议和负责人字段。

## 跟进与待办

新记录使用 `workspace_followups`，区分日常服务、定增、优先劣后；可关联客户的有效产品批次。保存沟通不会更改定增阶段。下次联系时间保存为 UTC，浏览器按当地时间显示；可以标记待办完成。完成操作和新增操作均审计。

`followups` 旧表保留，显示为“历史跟进 · 未分类”。旧计划完成状态不明，不纳入新待办计数。新旧记录在同一页面和客户卡片汇总展示，不复制数据。

日常服务跟进对当前有此客户权限的账号可见；产品跟进只对该产品有权限的账号可见。我的跟进默认显示自己记录的，可切换全部可见；工作台显示本人记录且已到期、尚未完成的新待办。此版本不发送站外提醒。

优先劣后跟进锚定稳定的活动记录，后续匹配或纠正 TW 时沿当前活动关联到客户卡片。撤销会删除已有关联跟进的活动记录时，拒绝撤销并提示修订资料。旧客户导入撤销保护同时计入新跟进，客户合并迁移内部 ID 锚定的跟进。

全局工作台使用 `/api/workspace/dashboard`，展示去重客户总数、单列待匹配记录、近 14 天统一跟进和可见到期待办。定增与优先劣后分卡展示参与人数和金额，显示交叉参与人数。定增金额优先使用已参与批次记录，仅完全没有批次记录时回退到旧客户已参与金额，避免重复累计。优先劣后按正协议金额统计，未匹配金额计入、人数单列。旧分析放在定增内部并明确注明旧口径。

## 发布

服务启动时自动创建新增表与索引，兼容 SQLite/PostgreSQL SQL；无破坏性旧表迁移。前端资源版本已更新。先备份，再更新代码和重启。使用管理员与两个不同业务负责人账号验收客户卡片、资料导入入口、写跟进及权限隔离。当前本地自动测试和浏览器验收使用独立 SQLite 演示库，未改线上资料；生产 PostgreSQL 仍需发布前验证。

## 共用主档更新与升级

- 客户中心提供“更新共用客户名单”，复用既有 Excel 预览能力；上传预览明确提示共用主档新增、TW 补关联和冲突数量。优先劣后内上传总名单同样更新共用主档。
- 首次启动升级自动处理已发布的历史总名单，按 TW 补入缺少的客户。事务内执行并记录 `shared_customers.synchronized` 审计；可重复执行，不复制已有客户，不改变已有产品归属。新上传与主档同步处于同一事务。
- 已归档 TW 不自动恢复；多个旧客户指向同一 TW 不自动合并。导入预览显示待处理冲突。普通经理仍按负责业务与数据范围查看，新增待分配客户由全量管理员分配后再开放，绝不因为共用名单自动扩大另一产品的权限。
- 撤销来源快照只撤销该来源版本，不删除已建立的共用主档或其他产品记录。需要删除客户时走正常归档流程。导入空白、下一周漏行均不等于删除客户。
- 新增 100 位客户、其中 10 位参与优先劣后：全量客户池增加 100；优先劣后参与数增加 10；定增参与数不变。所有计数仍基于当前账号权限与 TW 是否匹配。
- 验证：62 项自动测试通过，包含 100/10 示例、重复导入、历史回填、金额防重、负责人保护、已归档记录以及不同产品负责人可见范围。浏览器使用独立合成数据验证总名单上传预览、保存、客户池和工作台更新。环境没有 PostgreSQL 服务，尚未进行 PostgreSQL 实例验收。

## 2026-09-21：负责人跟随客户

- 客户主档为唯一当前负责人。定增、优先劣后、客户卡片及查看权限同步。原表负责人作为来源历史保留，不代表另一套当前归属。
- 升级启动、上传保存、身份关联后，已有活动的有效负责人自动补全尚未分配的主档。两边已分配且不一致时不覆盖，进入优先劣后“待处理中心 → 确认统一负责人”。可选择沿用当前主档，也可换人。
- 领导主动指派对所有产品生效，并保护该决定不被后续上传覆盖。编辑窗口带客户版本，过期提交须刷新确认。
- 经纪人默认绑定只补全尚未分配的普通服务客户；更改或停用绑定不会改动既有归属。已有客户转交通过“修改负责人”操作。客户从普通服务转为产品意向时继续保留当前负责人。
- 解除错误 TW 关联或撤销全部对应活动来源时，只撤回由活动自动补全且未被人工改过的负责人。人工指派保留；所有变更写归属历史及审计。撤销活动修订不会撤销已确认的客户级人工归属。
- 所有更改仍需提交、推送并更新服务才会在线上生效。本地测试采用 SQLite；未直接操作生产数据库。

## ICC 开户状态导入开关

在“优先劣后 → 资料导入”提供“跳过未开户客户（ICC 开户状态为空）”，界面默认开启并记住本浏览器上次选择。按 ICC 原表开户状态是否为空筛选（包含仅空格的单元格）；“已提交”等非空值仍导入，不推断开户成功或 TW 存在。对客户名单、资产、持仓不筛选。

预览显示原表人数、本次纳入人数、跳过人数，可展开查看跳过姓名及原表行号。关闭开关重新读取可补录全部；日后原表状态非空再上传，也能补入。开关或文件、日期改变会使旧预览失效，必须重新读取，避免按旧条件保存。已保存活动不会因本次筛选删除；本批次记录数可能包含历史保留记录。筛选结果随上传历史保存，原文件仍留作审计来源。旧 API 客户端未传 `skipIccBlankAccountStatus` 时兼容原有全量导入行为。
