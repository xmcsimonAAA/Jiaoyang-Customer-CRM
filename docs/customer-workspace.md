# 客户中心与两个产品业务

2026-09-16：侧边栏按日常工作、客户中心、产品业务、系统管理组织。

- 日常工作：工作台、我的跟进。
- 客户中心：全部客户，按已确认 TW 汇总；没有 TW 的旧客户按内部 ID，港安待匹配记录按批次与稳定记录键保留，绝不按同名自动合并。
- 定增：批次管理、业务客户、资料录入、导入复核、负责人分配、经纪人绑定、业务表头、业务跟进。原路由兼容。
- 优先劣后：批次记录、客户综合查询、资料导入、上传历史、负责人分配、业务跟进。
- 系统管理：人员与权限、操作日志。

## 客户卡片和权限

卡片汇集当前账号有权查看的定增资料、优先劣后资料、共用资产与持仓、跟进时间线。定增权限仍依据旧客户归属/团队/协同；优先劣后权限依据独立服务归属。同一 TW 的资产与持仓可供任一业务中有该客户权限的账号查看；产品私有记录不会因此互通。未参与产品与无可见产品资料不混作同一概念。

这一步是按 TW 汇总的客户视图，不迁移或覆盖线上旧客户主表。联系方式仍从有权查看的旧客户记录读取，优先劣后批次保留自己的经纪人、协议和负责人字段。

## 跟进与待办

新记录使用 `workspace_followups`，区分日常服务、定增、优先劣后；可关联客户的有效产品批次。保存沟通不会更改定增阶段。下次联系时间保存为 UTC，浏览器按当地时间显示；可以标记待办完成。完成操作和新增操作均审计。

`followups` 旧表保留，显示为“历史跟进 · 未分类”。旧计划完成状态不明，不纳入新待办计数。新旧记录在同一页面和客户卡片汇总展示，不复制数据。

日常服务跟进对当前有此客户权限的账号可见；产品跟进只对该产品有权限的账号可见。我的跟进默认显示自己记录的，可切换全部可见；工作台显示本人记录且已到期、尚未完成的新待办。此版本不发送站外提醒。

优先劣后跟进锚定稳定的活动记录，后续匹配或纠正 TW 时沿当前活动关联到客户卡片。撤销会删除已有关联跟进的活动记录时，拒绝撤销并提示修订资料。旧客户导入撤销保护同时计入新跟进，客户合并迁移内部 ID 锚定的跟进。

工作台下方原经营统计暂保留原定增客户口径并显式标注，不把两个产品的金额相加；上方提供两个产品入口与统一待办。

## 发布

服务启动时自动创建新增表与索引，兼容 SQLite/PostgreSQL SQL；无破坏性旧表迁移。前端资源版本已更新。先备份，再更新代码和重启。使用管理员与两个不同业务负责人账号验收客户卡片、资料导入入口、写跟进及权限隔离。当前本地自动测试和浏览器验收使用独立 SQLite 演示库，未改线上资料；生产 PostgreSQL 仍需发布前验证。
